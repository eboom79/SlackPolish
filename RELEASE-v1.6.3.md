# SlackPolish v1.6.3 Release Notes

**Release Date:** September 6, 2026
**Build:** 3

## SlackPolish in Jira and Confluence

The same hotkey, the same prompts and the same protections you have in Slack now
work in Jira and Confluence comments, through a Chrome extension that ships in
this repository (`extension/`).

## What's New

### Chrome extension: polish Jira / Confluence comments
- Press the hotkey in a Jira or Confluence comment editor and the comment — or
  just the text you selected — is polished with the same style prompts as Slack
- **Mentions, links, inline code, emoji and quoted paragraphs are kept verbatim.**
  They are replaced by tokens before the model sees the text, put back afterwards
  and verified after write-back; if a protected element ever went missing the pill
  turns red and Ctrl+Z restores the original
- Tokens the model drops are re-anchored on their text or appended; a quoted line
  the model rewrote gets its verbatim quote back; merged lines are retried once
  with the exact line count — the same repair rules as in Slack
- The familiar SlackPolish pill shows *Improving* → *Active*, or says exactly what
  is wrong ("Needs API Key", "click into the comment editor first")
- The extension logs where the hotkey is pressed (Slack, Atlassian or another
  site) in an activity log you can copy as JSON; nothing leaves your machine
  except the polish request to OpenAI

### One settings menu, on both sides
- The extension's settings menu is the **same menu as in Slack**: Language, Style,
  Hotkey, Personal Style, the OpenAI key, Save / Cancel — same labels, same
  option texts, applied on Save
- Both menus have a **Sync settings with Chrome / Slack** checkbox. When you press
  Save with it checked, language, style, hotkey and personal style are sent to the
  other side. Nothing syncs on a hotkey press; polishing never waits on anything
  but OpenAI
- **One OpenAI key for both.** A key entered in either menu is valid for both;
  there is no separate-key option
- The bridge is the SlackPolish launcher (it already runs beside Slack): the
  extension keeps a small local connection to it, a Save in Slack is relayed at
  once, a Save in the extension is written into Slack and the Slack scripts reload
  it. A Save made while Slack is not running through SlackPolish is kept and sent
  on the next connection. Slack-only options (Smart Context, emoji signature) are
  not mirrored

### Slack
- **F12 (settings) and F10 (channel summary) keep working after a launcher
  restart.** Restarting the launcher while Slack stays open re-injects the
  runtime; the two scripts used to add a second hotkey handler each time, which
  opened the settings menu and closed it again at once
- The settings menu gains the **Sync settings with Chrome** checkbox (off by
  default)

### For developers
- `extension/vendor/slack-config.js` is a byte-identical copy of `slack-config.js`
  (regenerated by `increment-version.py` and the installer), so prompts, styles,
  languages and model settings have one source of truth; a unit test enforces it
- New suites: extension unit tests (menu parity with Slack, token repair, sync
  semantics), a launcher bridge test with a fake Slack, and a Chrome end-to-end
  suite that loads the extension in Chrome for Testing, polishes a real
  ProseMirror editor against a mock OpenAI and a mock launcher, and asserts zero
  launcher traffic while polishing. Details in `extension/README.md`

## Installation

### macOS Apple Silicon
```bash
python3 installers/install-slack-MAC-ARM.py
```

Then launch (or re-launch) from `~/Desktop/SlackPolish.app`.

### Chrome extension (one time)
1. Open `chrome://extensions`, turn on **Developer mode**
2. **Load unpacked** → `~/Library/Application Support/SlackPolish Runtime/chrome-extension/`
3. Click the SlackPolish toolbar icon: if your key and settings are already saved
   in Slack, they appear there within a moment
4. After a SlackPolish update: click **Reload** on the extension card, then reload
   any Jira tab that was already open (Chrome keeps the old script in open tabs)

## Verification

- `node tests/run-all-tests.js`
- `node tests/e2e/chrome-extension-hotkey.mjs` (Chrome for Testing; see `extension/README.md`)
- `node tests/e2e/run-slack-e2e.mjs` (live Slack; requires the launcher and an API key)

## Notes

- The extension polishes only inside Atlassian comment editors; on other sites the
  hotkey is logged and the pill is shown, nothing is changed
- Ctrl+Tab is listed for parity with Slack but Chrome reserves it for switching
  tabs; use Ctrl+Shift or Ctrl+Alt in the browser
