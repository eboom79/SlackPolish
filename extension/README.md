# SlackPolish Chrome extension (Jira / Confluence)

SlackPolish outside Slack: press the SlackPolish hotkey (**Ctrl+Shift**) while
writing a Jira or Confluence comment and the comment — or just the text you
selected — is polished with **the same prompts, styles and protections as in
Slack**. Mentions, links, inline code, emoji and quoted lines (`>`) are replaced
by tokens before the model sees the text, put back afterwards, and verified
after write-back; if anything protected went missing the write-back is flagged
and **Ctrl+Z** restores the original.

The extension also records where the hotkey was pressed (surface
`atlassian` / `slack-web` / `other`, host, path, title, the focused editor's
text and a compact DOM vocabulary — attribute *names*, never values, never the
query string). Events live in `chrome.storage.local` (last 200); the toolbar
popup shows them, the polish results and lets you copy them as JSON or clear.

## Setup

1. Install/stage: the macOS installer copies the extension to
   `~/Library/Application Support/SlackPolish Runtime/chrome-extension/`
   (or load it straight from `extension/` in this repo).
2. `chrome://extensions` → **Developer mode** → **Load unpacked** → choose that folder.
3. Click the SlackPolish toolbar icon → **Polish in Jira / Confluence**:
   tick **Polish on Ctrl+Shift**, paste your **OpenAI API key**, pick style and
   language. (Same catalog as Slack; the key stays in `chrome.storage.local`.)
4. Open a Jira issue, click into the comment editor, type, press **Ctrl+Shift**.
   The SlackPolish pill (bottom-left) shows *Improving* → *Active*.

After a SlackPolish update, click **Reload** on the extension card.

The model is called from the extension's background worker (`api.openai.com`
host permission); the content script never talks to the network. The comment is
sent to OpenAI only when polishing is enabled and you press the hotkey.

## How a polish works

1. `shared/atlassian-adapter.js` reads the ProseMirror document into Slack-style
   model text (`> ` quotes, `• ` / `1. ` lists) with tokens
   `__SLACKPOLISH_{MENTION|LINK|CODE|EMOJI|QUOTE}_n__` for protected entities
   (a selection is extracted the same way from `range.cloneContents()`).
2. `shared/polish-core.js` builds the prompt exactly like the Slack script
   (`vendor/slack-config.js` is a byte-identical copy of `slack-config.js`, so
   prompts, styles, languages and model settings cannot drift), calls the worker,
   retries once when lines were merged, and repairs the answer: tokens the model
   dropped are re-anchored on their text or appended, rewritten quote lines get
   their token back, echoed tokens are stripped.
3. The adapter rebuilds HTML (entity markup verbatim) and inserts it through a
   synthetic paste — after waiting for Ctrl/Shift to be released, because
   ProseMirror pastes plain text while Shift is held — then re-extracts and
   verifies that no protected entity disappeared.

## Layout

- `vendor/slack-config.js` — copy of the root config (regenerated by `increment-version.py` and the installer)
- `shared/hotkey.js` — chord detection + held-modifier tracking, same semantics as the Slack script
- `shared/surface.js` — host → surface classification
- `shared/status-badge.js` — the SlackPolish status pill, copied from the Slack script
- `shared/editor.js` — finds/describes the focused editor (ProseMirror, Quill, contenteditable, textarea)
- `shared/atlassian-adapter.js` — ProseMirror extract / rebuild / write-back
- `shared/polish-core.js` — prompt, model-output repair, verification
- `content/hotkey-logger.js` — content script (all URLs, top frame): logging + the polish flow
- `background.js` — persists events, badge count, OpenAI call
- `popup/` — settings and the log

## Tests

`tests/unit/test_extension_hotkey_logger.js` and
`tests/unit/test_extension_polish_core.js` (unit, part of `tests/run-all-tests.js`);
`tests/e2e/chrome-extension-hotkey.mjs` launches a throwaway browser with the
extension, presses the real chord over CDP and polishes a real ProseMirror
editor against a mock OpenAI endpoint (faithful model, selection only, careless
model that drops tokens). Google Chrome's branded builds ignore
`--load-extension`, so the live test needs **Chrome for Testing** (or Chromium):

```bash
npx @puppeteer/browsers install chrome@stable --path ~/Library/Caches/slackpolish-browsers
node tests/e2e/chrome-extension-hotkey.mjs
```

Loading the extension unpacked in your normal Chrome is unaffected by that
restriction.
